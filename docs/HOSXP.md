# นัดและบุคลากรจาก HOSxP

เจ้าหน้าที่สร้าง เลื่อน และยกเลิกนัดใน HOSxP เท่านั้น เว็บแสดงปฏิทินและใช้ตัวส่ง MOPH Alert เดิม ไม่สร้างบัญชีล็อกอินจาก doctor และไม่เขียนกลับฐาน HOSxP

## บุคลากรและการจับคู่นัด

ตาราง doctor เป็นทะเบียนบุคลากรของโรงพยาบาล: active=Y ยังทำงาน ส่วน N หรือค่าอื่นไม่ใช่บุคลากรที่ใช้งานในระบบแจ้งเตือน หน้าเว็บอ่าน doctor เมื่อเปิดหน้าบุคลากร/นัด และ worker อ่าน doctor ก่อนอ่านนัดทุกครั้ง ไม่ต้องนำเข้ารายชื่อหรือสร้างหน่วยงานก่อน

จับคู่บุคลากรเดิมด้วย CID เท่านั้น ไม่รวมคนจากชื่อ รักษาการตั้งค่าปิดรับข้อความของบุคลากรเดิม ส่วนบุคลากรใหม่ที่มี CID ถูกต้องพร้อมรับข้อความตามการตั้งค่า LIVE/DRY_RUN ของระบบ CID เก็บเข้ารหัสและ HMAC ไม่คืนให้ browser

รายชื่อที่ CID ว่าง/ไม่ถูกต้องยังแสดงในหน้าบุคลากร แต่ไม่จับคู่นัดหรือส่งข้อความ หาก CID ซ้ำหรือขัดกับตัวบุคคลเดิม ระบบหยุด sync ชุดนั้นให้ตรวจต้นทาง ผู้ที่พ้นสภาพดูได้ด้วยตัวกรองสถานะ ไม่สร้างประวัติตำแหน่งหรือหน่วยงานจากการเดา ผู้ใช้ที่จำกัดสิทธิ์หน่วยงานยังเห็นเฉพาะทะเบียนที่มีหน่วยงานตรงสิทธิ์ ผู้ดูแลเห็นทั้งหมด

จับคู่นัดด้วย doctor.cid = patient.cid และ patient.hn = oapp.hn เฉพาะ doctor ที่ active=Y ไม่ใช้ oapp.doctor ระบุตัวผู้รับนัด เพราะคอลัมน์นั้นคือผู้ให้บริการของนัด

## ห้องบริการและปีงบประมาณ

ใช้สี่ห้องที่กำหนดจากไฟล์ kskdepartment ในตัวกรองปฏิทิน ไม่มีหน้าตั้งค่าหรือฟอร์มเพิ่มหน่วยงาน:

| depcode | ห้อง |
| --- | --- |
| 033 | กายภาพบำบัด |
| 006 | LAB / ห้องชันสูตร |
| 019 | ทันตกรรม |
| 023 | แพทย์แผนไทย |

กรองนัดด้วย oapp.depcode เฉพาะสี่ห้อง ชื่อห้องต้นทางอ่านจาก kskdepartment.department ปีงบประมาณคำนวณจาก oapp.nextdate เช่น 30 กันยายน 2569 เป็นปี 2569 และ 1 ตุลาคม 2569 เป็นปี 2570 ไม่มีการสร้างหรือเลือกปีด้วยมือ

หน้าแรกแสดงปฏิทินเดือนปัจจุบันทันที แม้ไม่มีนัดหรือไม่มีแถว fiscal_years ถ้าฐานข้อมูลล่ม ปฏิทินยังอยู่พร้อมข้อความโหลดนัดไม่สำเร็จ ป้ายปีเปลี่ยนตามเดือนที่แสดง หน้าแรกแสดงจำนวนรวมโดยไม่มีชื่อ/CID และโหลดใหม่ทุก 30 วินาที รายชื่อดูหลังล็อกอิน

## ติดตั้งและอัปเดต

ตั้ง HOSXP_DB_* สำหรับบัญชี SELECT บน doctor, patient, oapp, kskdepartment แยกจาก DB_* ของฐานเว็บ ต้องตั้ง DATA_ENCRYPTION_KEY และ CID_HMAC_KEY ตามคู่มือเดิม ห้ามเปลี่ยนกุญแจของระบบที่มีข้อมูลเข้ารหัสแล้ว

หยุดเว็บ/worker รุ่นเก่า แล้วรันในโฟลเดอร์โปรเจกต์:

```sh
git pull origin main
npm ci
npm run db:migrate
npm run hosxp:sync
npm run dev
```

เปิดอีก terminal เพื่อรันต่อเนื่อง:

```sh
npm run worker
```

Production ใช้ npm run build แล้ว npm start แทน dev ถ้าใช้ Compose profile app ให้ rebuild app/worker ด้วยโค้ดใหม่

hosxp:sync ดึงบุคลากรและนัด พร้อมพิมพ์จำนวนสรุป ไม่มีการส่งข้อความในคำสั่งนี้ แต่การเปลี่ยนนัดหลัง baseline อาจสร้างคิวที่ worker จะส่งภายหลัง Migration 007 เพิ่มรหัส/ชื่อ doctor ใน employees ไม่ต้อง migrate ฐาน HOSxP การตั้งข้อมูลครั้งแรกไม่ส่งนัดเก่าย้อนหลังทั้งหมด

หากยังเห็นช่องเลือก/เพิ่มปีงบหรือฟอร์มเพิ่มหน่วยงาน ให้ตรวจ git log -1 --oneline ในโฟลเดอร์ที่รันจริง หยุด process เก่า เริ่มใหม่ แล้วรีเฟรช browser

## API และการส่ง

- GET hosxp/oapp?from=2026-10-01&to=2026-10-31&room=006&personnel=CODE อ่านนัดตามบุคลากรผู้มีนัด ไม่เลือกตัวกรองจะแสดงทุกคนในสิทธิ์และทั้งสี่ห้อง
- GET hosxp/options คืน code/name บุคลากรที่ยังทำงานตามสิทธิ์ พร้อมตัวเลือกห้อง
- ทั้งสอง endpoint ต้องล็อกอินและมี appointment.read กับ employee.read
- API เพิ่ม/แก้นัด นำเข้านัด สร้าง/แก้ปีงบ เพิ่ม/แก้ข้อมูลตั้งต้น เพิ่ม/แก้/นำเข้าบุคลากร และผู้มีสิทธิ์ประจำปี (members, plans) ตอบ 410

Worker อ่านนัดตั้งแต่วันนี้ถึงอีก 366 วัน พัก 15 วินาทีระหว่างรอบ ใช้ oapp_id และ fingerprint กันส่งซ้ำ สถานะนัดใช้งานกำหนดด้วย HOSXP_ACTIVE_STATUS_IDS ค่าเริ่มต้น NULL,1 (นัดปกติ) ปฏิทินหน้าแรกอ่านนัดจาก HOSxP โดยตรงตามสถานะเดียวกัน บุคลากรจับคู่ด้วยชื่อ (patient.fname+lname = doctor.name ไม่สนช่องว่าง) หรือ CID ที่ไม่ว่าง ก่อนส่ง LIVE จะอ่านนัดและตรวจ doctor.active อีกครั้ง เมื่อแหล่งข้อมูลล่มจะไม่ส่งโดยใช้ข้อมูลที่ยืนยันไม่ได้ สถานะ UNKNOWN ไม่ retry อัตโนมัติ

ข้อมูลนัดและรายงานเก่ายังคงอยู่สำหรับอ่านย้อนหลัง ระบบส่งจริงต้องเปิดการแจ้งเตือนและตั้งค่า MOPH ตามระบบเดิม การ GET จากเว็บไม่ส่งข้อความ
